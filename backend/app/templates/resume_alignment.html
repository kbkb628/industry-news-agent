This page translates the implemented monitor runtime into concise, recruiter-readable language. It is meant to help position the project as a backend system with visible orchestration, reliability concerns, and product-facing outcomes.

Interview talking points
  • Built a FastAPI-based monitor loop that turns topic context into actionable push decisions.
  • Used LangGraph for top-level supervision, with candidate-level fetch, extract, and evaluate task orchestration inside the run.
  • Exposed planning, candidate task evidence, trace events, push records, and evaluation signals through APIs and readable pages.
Suggested resume framing
  • Emphasize supervisor-driven multi-agent orchestration plus candidate-level task scheduling.
  • Describe fallbacks, task ledger evidence, and quality metrics as signs of resilience-minded engineering.
  • Use this page as a bridge between runtime truth, interview wording, and demo order.
Truth boundary
  • The top-level graph is `Supervisor -> Planner -> Retrieval -> CandidateTaskOrchestrator -> Finalize`.
  • Fetch, extract, and evaluate still exist as real specialist behaviors, but they run under the candidate task orchestrator instead of as top-level graph nodes.
  • Optional MCP, browser, judge, and history-index adapters remain boundaries unless the target runtime wires live services.

  • Show run detail and candidate task readback to explain bounded same-stage orchestration.
  • Finish with trace events, pushes, and quality metrics to show reliability and evaluation evidence.
